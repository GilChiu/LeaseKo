# Implementation Plan: Centralized Config Management

**Branch**: `017-centralized-config-management` | **Date**: 2026-05-06 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/017-centralized-config-management/spec.md`

## Summary

Split the existing flat `AppConfig` factory into four typed, domain-scoped config
factories (`app`, `database`, `redis`, `clerk`) using NestJS `registerAs()`. Extend
the Joi validation schema with two optional Clerk vars (`CLERK_ISSUER`,
`CLERK_AUDIENCE`). Refactor `main.ts` to read config from the validated
`ConfigService` instead of `process.env`. Update `ClerkTokenVerifierService` to
consume the `clerk` namespace. Update `.env.example` and config documentation.
Result: zero `process.env` usage outside `common/config/` files and `main.ts`
bootstrap → `main.ts` itself is also cleaned up.

#### Task 1.4 — Refactor `app.config.ts` to use `registerAs`

**File**: `apps/api/src/common/config/app.config.ts`

and Clerk fields — those now live in their own factories.

import { registerAs } from "@nestjs/config";

export interface AppConfig {
  nodeEnv: string;
  port: number;
  frontendUrl: string;
}

export const appConfig = registerAs(
  "app",
  (): AppConfig => ({
    nodeEnv: process.env.NODE_ENV ?? "development",

    frontendUrl: process.env.FRONTEND_URL!,
  }),

### Phase 4: Refactor `main.ts` to use `ConfigService`

**Goal**: Remove the four direct `process.env` reads from `main.ts`. After
`NestFactory.create(AppModule)` resolves, `ConfigModule` is loaded and
`ConfigService` is ready via `app.get()`.

#### Task 4.1 — Update `main.ts`

**File**: `apps/api/src/main.ts`

```typescript
import "reflect-metadata";
import { NestFactory } from "@nestjs/core";
import { ValidationPipe } from "@nestjs/common";
import { ConfigService } from "@nestjs/config";
import { DocumentBuilder, SwaggerModule } from "@nestjs/swagger";
import { AppModule } from "./app.module";
import { GlobalExceptionFilter } from "./common/filters/global-exception.filter";
import type { AppConfig } from "./common/config/app.config";

async function bootstrap(): Promise<void> {
  const app = await NestFactory.create(AppModule);

  const configService = app.get(ConfigService);
  const appConfig = configService.getOrThrow<AppConfig>("app");
  const { port, frontendUrl, nodeEnv } = appConfig;

  app.setGlobalPrefix("api/v1");
  app.enableCors({ origin: frontendUrl });
  app.useGlobalFilters(new GlobalExceptionFilter());
  app.useGlobalPipes(
    new ValidationPipe({
      whitelist: true,
      forbidNonWhitelisted: true,
      transform: true,
    }),
  );

  if (nodeEnv !== "production") {
    const config = new DocumentBuilder()
      .setTitle("LeaseKo API")
      .setDescription("LeaseKo Property Management SaaS API")
      .setVersion("1.0")
      .addBearerAuth()
      .build();
    const document = SwaggerModule.createDocument(app, config, {
      ignoreGlobalPrefix: true,
    });
    SwaggerModule.setup("api/docs", app, document);
  }

  await app.listen(port);
  // eslint-disable-next-line no-console
  console.log(`API running on http://localhost:${port}`);
  if (nodeEnv !== "production") {
    // eslint-disable-next-line no-console
    console.log(`Swagger UI available at http://localhost:${port}/api/docs`);
  }
}

void bootstrap();
```

> **Pattern**: `app.get(ConfigService)` is the standard NestJS approach for
> accessing the DI container from bootstrap. `getOrThrow<AppConfig>("app")`
> throws if the namespace was not registered — catches wiring errors early.

### Phase 5: Update `ClerkTokenVerifierService`

**Goal**: Consume the `clerk` namespace instead of the raw `CLERK_SECRET_KEY`
string key. Optionally pass `issuer` and `audience` to `verifyToken` when set.

#### Task 5.1 — Update `clerk-token-verifier.service.ts`

**File**: `apps/api/src/modules/auth/infrastructure/clerk-token-verifier.service.ts`

```typescript
import { Injectable, UnauthorizedException } from "@nestjs/common";
import { ConfigService } from "@nestjs/config";
import { verifyToken } from "@clerk/backend";
import type { ClerkConfig } from "../../../common/config/clerk.config";

@Injectable()
export class ClerkTokenVerifierService {
  constructor(private readonly config: ConfigService) {}

  async verify(
    token: string,
  ): Promise<{ userId: string; tenantId: string | null }> {
    try {
      const clerkConf = this.config.getOrThrow<ClerkConfig>("clerk");
      const payload = await verifyToken(token, {
        secretKey: clerkConf.secretKey,
        ...(clerkConf.issuer && { issuer: clerkConf.issuer }),
        ...(clerkConf.audience && { audience: clerkConf.audience }),
      });
      if (!payload.sub) {
        throw new UnauthorizedException();
      }
      const orgClaim = (
        payload as Record<string, Record<string, string> | undefined>
      ).o;
      const tenantId = orgClaim?.id ?? null;
      return { userId: payload.sub, tenantId };
    } catch {
      throw new UnauthorizedException();
    }
  }
}
```

> **Note**: `CLERK_JWKS_URL` is not passed to `verifyToken` — the Clerk SDK
> auto-derives the JWKS URL from `secretKey`. `CLERK_JWKS_URL` is validated and
> stored in config for future use (e.g., private-network overrides), but not
> passed here unless a specific use case arises.

## Clean Architecture Config Rules

| Layer | Config Access | Rule |
|---|---|---|
| Domain | None | Domain entities MUST NOT import config or environment values |
| Application | None (default) | Use cases receive config-derived values via constructor parameters only if unavoidable |
| Infrastructure | Via `ConfigService` injection | Infrastructure services (repositories, external API clients) inject `ConfigService` and access typed namespaces |
| Presentation | None | Controllers and DTOs MUST NOT access config or environment values |
| Common/Config | `process.env` (ONLY here) | Config factories and validation schema are the sole `process.env` access point |
| Bootstrap (`main.ts`) | `app.get(ConfigService)` | After `NestFactory.create()`, bootstrap uses `ConfigService` — not `process.env` |

## Notes for Subsequent Features

### Feature 018 — Global Exception Filter

Config is not directly related, but the exception filter in `GlobalExceptionFilter`
may benefit from injecting `AppConfig` to determine response verbosity (`nodeEnv`).
Currently it reads `process.env.NODE_ENV` directly — if that pattern appears, it
should be refactored at that time to match the established config pattern.

### Feature — Swagger Setup Enhancement

`main.ts` now reads `nodeEnv` from `ConfigService`. The Swagger toggle condition
(`nodeEnv !== 'production'`) is already correct. If Swagger config (title, version,
description) needs to be dynamic, those values can be added to `AppConfig`.

### Feature — BullMQ Integration

When BullMQ is added, `QueuesModule.forRootAsync()` MUST inject `ConfigService`
and read `redis.url` from the `redis` namespace:

```typescript
BullModule.forRootAsync({
  inject: [ConfigService],
  useFactory: (config: ConfigService) => ({
    connection: { url: config.getOrThrow<string>('redis.url') },
  }),
})
```

### Feature — Auth Config Cleanup

`ClerkTokenVerifierService` currently uses only `secretKey`, `issuer`, and
`audience`. When JWKS URL override is needed for a private-network deployment,
update the `verifyToken` call to include `jwksUrl` from `clerkConf.jwksUrl`.
