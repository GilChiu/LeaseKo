# Implementation Plan: Global Exception Filter and Standard API Error Responses

**Branch**: `018-global-exception-filter` | **Date**: 2026-05-06 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/018-global-exception-filter/spec.md`

## Summary

Refactor the existing `GlobalExceptionFilter` in-place to emit a standard
`ApiErrorResponse` shape (`{ success: false, error: { code, message, statusCode,
timestamp, path, details? } }`). Create an `ErrorCode` const registry, a
`PrismaErrorMapper` safety-net utility, and an `ApiErrorResponse` TypeScript
interface. Update the Swagger `ErrorResponseDto` to match the new shape. Pass
`nodeEnv` to the filter constructor so production responses omit internal messages.
Add a unit test for the filter. Document the error contract in `docs/api-errors.md`.

### Phase 2: Prisma Error Mapper

**Goal**: Create a pure mapping utility that converts Prisma-specific error instances
to safe `{ status, code, message }` tuples. No NestJS dependencies — testable in isolation.

#### Task 2.1 — Create `common/errors/prisma-error.mapper.ts`

```typescript
import {
  PrismaClientKnownRequestError,
  PrismaClientInitializationError,
} from "@prisma/client/runtime/library";
import { HttpStatus } from "@nestjs/common";
import { ErrorCode } from "./error-codes";

interface MappedPrismaError {
  status: number;
  code: ErrorCode;
  message: string;
}

export function mapPrismaError(error: unknown): MappedPrismaError | null {
  if (error instanceof PrismaClientInitializationError) {
    return {
      status: HttpStatus.SERVICE_UNAVAILABLE,
      code: ErrorCode.SERVICE_UNAVAILABLE,
      message: "The database is temporarily unavailable",
    };
  }

  if (!(error instanceof PrismaClientKnownRequestError)) {
    return null;
  }

  switch (error.code) {
    case "P2002":
      return {
        status: HttpStatus.CONFLICT,
        code: ErrorCode.CONFLICT,
        message: "A record with this value already exists",
      };
    case "P2025":
      return {
        status: HttpStatus.NOT_FOUND,
        code: ErrorCode.NOT_FOUND,
        message: "The requested resource was not found",
      };
    case "P2003":
      return {
        status: HttpStatus.CONFLICT,
        code: ErrorCode.CONFLICT,
        message: "Referenced resource does not exist or a constraint was violated",
      };
    default:
      return {
        status: HttpStatus.INTERNAL_SERVER_ERROR,
        code: ErrorCode.INTERNAL_SERVER_ERROR,
        message: "A database error occurred",
      };
  }
}
```

### Phase 3: Refactor GlobalExceptionFilter

**Goal**: Replace the existing filter implementation with one that emits the
standard `ApiErrorResponse` shape. Constructor takes `nodeEnv` for prod/dev behavior.

#### Task 3.1 — Refactor `common/filters/global-exception.filter.ts`

**Key logic**:

1. `if (exception instanceof HttpException)`:
   - Get status with `exception.getStatus()`
   - Get body with `exception.getResponse()`
   - If body has array `message` → `VALIDATION_ERROR` + parse fields
   - If body has `code` field → use it (custom domain code support)
   - Otherwise → derive `ErrorCode` from HTTP status (see table)
   - 4xx → do NOT log
2. `else if (mapPrismaError(exception) !== null)`:
   - Use mapped status/code/message
   - Do NOT log (Prisma errors are expected operational conditions)
3. `else` (unknown error):
   - Status 500, `INTERNAL_SERVER_ERROR`
   - Log: method, path, statusCode, error name, error message
   - `message`: original message in dev, generic in prod
   - Never include stack trace in response

**HTTP status → ErrorCode default derivation**:

```typescript
function defaultErrorCode(status: number): ErrorCode {
  const map: Record<number, ErrorCode> = {
    400: ErrorCode.BAD_REQUEST,
    401: ErrorCode.UNAUTHORIZED,
    403: ErrorCode.FORBIDDEN,
    404: ErrorCode.NOT_FOUND,
    409: ErrorCode.CONFLICT,
    500: ErrorCode.INTERNAL_SERVER_ERROR,
    503: ErrorCode.SERVICE_UNAVAILABLE,
  };
  return map[status] ?? (status >= 500
    ? ErrorCode.INTERNAL_SERVER_ERROR
    : ErrorCode.BAD_REQUEST);
}
```

**Validation field extraction** from `class-validator` array messages:

```typescript
// message: "email must be an email" → field: "email", msg: "must be an email"
function parseValidationMessages(messages: string[]): ApiErrorDetails {
  const fieldMap = new Map<string, string[]>();
  for (const msg of messages) {
    const spaceIdx = msg.indexOf(" ");
    if (spaceIdx === -1) {
      const existing = fieldMap.get("_") ?? [];
      fieldMap.set("_", [...existing, msg]);
    } else {
      const field = msg.substring(0, spaceIdx);
      const constraint = msg.substring(spaceIdx + 1);
      const existing = fieldMap.get(field) ?? [];
      fieldMap.set(field, [...existing, constraint]);
    }
  }
  return {
    fields: Array.from(fieldMap.entries()).map(([field, messages]) => ({
      field,
      messages,
    })),
  };
}
```

  @ApiProperty({ example: "Unauthorized" })
  message!: string;

  @ApiProperty({ example: 401 })

  success!: false;

  @ApiProperty({ type: ApiErrorBodyDto })

}

## Error Code Reference

| Code | HTTP | Trigger |
|---|---|---|
| `VALIDATION_ERROR` | 400 | `ValidationPipe` rejects DTO (array message from class-validator) |
| `BAD_REQUEST` | 400 | `BadRequestException` with string message |
| `UNAUTHORIZED` | 401 | `UnauthorizedException` (JWT guard, missing token) |
| `FORBIDDEN` | 403 | `ForbiddenException` (tenant guard, missing org context) |
| `TENANT_CONTEXT_REQUIRED` | 403 | Custom code in `ForbiddenException` body |
| `NOT_FOUND` | 404 | `NotFoundException`, or Prisma P2025 |
| `CONFLICT` | 409 | `ConflictException`, or Prisma P2002/P2003 |
| `DATABASE_CONSTRAINT_ERROR` | 409 | Reserved for future domain-level DB constraint errors |
| `SERVICE_UNAVAILABLE` | 503 | `PrismaClientInitializationError` (connection failure) |
| `INTERNAL_SERVER_ERROR` | 500 | Any unhandled `Error` |

## Logging Rules

| Scenario | Log Level | Fields Logged |
|---|---|---|
| Unknown 5xx error | `error` | `method`, `path`, `statusCode=500`, `error.name`, `error.message`, stack (dev only) |
| Prisma unknown code mapped to 5xx | `error` | Same as above |
| Any 4xx `HttpException` | None | — |
| Prisma known error mapped to 4xx | None | — |

**Security**: `Authorization` header, token strings, passwords, JWT payload fields — NEVER logged.

## Notes for Subsequent Features

### Feature — Swagger Error Documentation Coverage

`ErrorResponseDto` now matches the standard shape. Future Swagger work can use it
consistently on all endpoints via `@ApiResponse({ status: 400, type: ErrorResponseDto })`.
Consider creating status-specific subclasses (`Error400Dto`, `Error401Dto`) if
the Swagger spec needs per-status example differentiation.

### Feature — Testing Foundation

The `global-exception.filter.spec.ts` unit test establishes the pattern for
infrastructure testing. Future filter tests, guard tests, and interceptor tests
should follow the same `createMockHost()` mock pattern.

### Feature — Request ID Middleware

When request ID middleware is added:
1. Add `requestId` to the request object via middleware
2. Update `GlobalExceptionFilter.catch()` to read `request.requestId` and include
   it in the `ApiError` object
3. No change to `ErrorCode`, `ApiErrorResponse` interface, or `ErrorResponseDto`
   required — `requestId` is already `optional` in the interface.

### Feature — Observability / Logging Improvements

The current `Logger` usage is minimal (NestJS built-in). When a structured logging
library (e.g., `pino`, `winston`) is added, only the `this.logger.error()` call in
the filter needs to be updated — the rest of the filter is unaffected.
