existing unit test to mock `ConfigService` and add two new test cases. No new

### Phase 1: Update HealthResponseDto

**Goal**: Add `uptime` and `environment` to the DTO so TypeScript knows the return type
and Swagger renders the new fields. This is the foundation — the controller update depends on it.

#### Task 1.1 — Modify `health-response.dto.ts`

```typescript
import { ApiProperty } from "@nestjs/swagger";

export class HealthResponseDto {
  @ApiProperty({ example: "ok", description: "API liveness status" })
  status!: string;

  @ApiProperty({ example: "api", description: "Service identifier" })
  service!: string;

  @ApiProperty({
    example: "2026-05-06T12:00:00.000Z",
    description: "ISO 8601 UTC timestamp of the response",
  })
  timestamp!: string;

  @ApiProperty({
    example: 42.37,
    description: "Process uptime in seconds since the API last started",
  })
  uptime!: number;

  @ApiProperty({
    example: "development",
    description:
      "Runtime environment — one of: development, staging, production",
  })
  environment!: string;
}
```

### Phase 2: Update HealthController

**Goal**: Inject `ConfigService`, read `nodeEnv` from the `"app"` namespace, and
include `uptime` and `environment` in the response. Keep all existing decorators unchanged.

#### Task 2.1 — Modify `health.controller.ts`

```typescript
import { Controller, Get } from "@nestjs/common";
import { ConfigService } from "@nestjs/config";
import { ApiOkResponse, ApiOperation, ApiTags } from "@nestjs/swagger";
import { Public } from "../../../common/decorators/public.decorator";
import type { AppConfig } from "../../../common/config/app.config";
import { HealthResponseDto } from "./dto/health-response.dto";

@ApiTags("System")
@Controller()
export class HealthController {
  constructor(private readonly configService: ConfigService) {}

  @Get("health")
  @Public()
  @ApiOperation({
    summary: "Health check",
    description:
      "Returns API liveness status. Public — no authentication required.",
  })
  @ApiOkResponse({ type: HealthResponseDto, description: "API is healthy" })
  check(): HealthResponseDto {
    const { nodeEnv } = this.configService.getOrThrow<AppConfig>("app");
    return {
      status: "ok",
      service: "api",
      timestamp: new Date().toISOString(),
      uptime: Math.round(process.uptime() * 100) / 100,
      environment: nodeEnv,
    };
  }
}
```

> `ConfigModule` is globally registered in `AppModule` — `ConfigService` is injected
> automatically by NestJS. No import changes to `HealthModule` are required.

### Phase 3: Update Unit Test

**Goal**: Update `health.controller.spec.ts` to pass a mock `ConfigService` to the
controller constructor and add test cases for the two new fields.

#### Task 3.1 — Modify `health.controller.spec.ts`

```typescript
import { ConfigService } from "@nestjs/config";
import { HealthController } from "./presentation/health.controller";

function mockConfigService(nodeEnv = "test"): ConfigService {
  return {
    getOrThrow: jest.fn().mockReturnValue({ nodeEnv }),
  } as unknown as ConfigService;
}

describe("HealthController", () => {
  let controller: HealthController;

  beforeEach(() => {
    controller = new HealthController(mockConfigService());
  });

  it('should return status "ok"', () => {
    const result = controller.check();
    expect(result.status).toBe("ok");
  });

  it('should return service "api"', () => {
    const result = controller.check();
    expect(result.service).toBe("api");
  });

  it("should return a valid ISO 8601 timestamp", () => {
    const result = controller.check();
    const parsed = Date.parse(result.timestamp);
    expect(Number.isNaN(parsed)).toBe(false);
    expect(new Date(result.timestamp).toISOString()).toBe(result.timestamp);
  });

  it("should return a positive uptime value", () => {
    const result = controller.check();
    expect(typeof result.uptime).toBe("number");
    expect(result.uptime).toBeGreaterThan(0);
  });

  it("should return the environment from ConfigService", () => {
    const envController = new HealthController(mockConfigService("production"));
    const result = envController.check();
    expect(result.environment).toBe("production");
  });
});
```

## Notes for Subsequent Features

### Feature — Readiness Endpoint (`GET /health/ready`)

A future `GET /health/ready` endpoint should check:
1. PostgreSQL: run a lightweight `SELECT 1` via `PrismaService`
2. Redis: ping via `ioredis` or `@nestjs/bull` connection check
3. BullMQ: optionally check queue queue connectivity

The liveness endpoint (`GET /health` / this feature) and the readiness endpoint are
separate concerns — never merge them. Kubernetes and similar platforms use separate
probes for each.

### Feature — Testing Foundation

Adding `ConfigService` injection to `HealthController` makes the test pattern for
controller-with-dependency visible. Future controller unit tests should follow the
same `mockService()` factory pattern established here.

### Feature — Structured Logging / Observability

The health endpoint currently returns `uptime` and `environment`. When a structured
logging library is added, server-side health metrics (memory usage, event loop lag)
may be emitted as log events — but they should never be included in the HTTP
response body.
