# Data Model: Prisma Migration Artifacts

**Feature**: 014-prisma-migrations  
**Date**: 2026-05-03  
**Scope**: Migration file structure and resulting database schema. No new Prisma models are added in this feature.

---

## Overview

This feature produces one migration artifact: the initial migration file that creates the `users`, `tenants`, and `tenant_memberships` tables in PostgreSQL. The Prisma schema models (`User`, `Tenant`, `TenantMembership`) were defined in Feature 013 and are unchanged.

---

## Migration File Structure

```
apps/api/prisma/
├── schema.prisma                          # Unchanged — already valid from Feature 013
└── migrations/
    └── <timestamp>_init_base_identity_tenant_models/
        └── migration.sql                  # AUTO-GENERATED by prisma migrate dev
```

### Migration tracking table
Prisma creates and manages `_prisma_migrations` in PostgreSQL automatically. This table records:
- `id` (UUID)
- `checksum` (SHA-256 of migration SQL)
- `finished_at` (timestamp)
- `migration_name`
- `logs`
- `rolled_back_at`
- `started_at`
- `applied_steps_count`

**Do not manually edit this table.**

## Global Model Exception Register

All three tables (`users`, `tenants`, `tenant_memberships`) are **global identity models** — they intentionally do NOT carry a `tenant_id` column. This is a documented exception to the Multi-Tenancy constitution principle.

See `docs/data-model.md` for the full rationale and register.

## Tables Confirmed NOT Present After This Migration

The following table names must NOT exist after the migration (no premature business models):

- `properties`
- `units`
- `leases`
- `payments`
- `maintenance_requests`
- `notifications`

The `_placeholder` table (from Feature 012's `prisma generate` workaround) will also NOT exist — the migration schema diff will not include it since the `Placeholder` model was removed in Feature 013.
