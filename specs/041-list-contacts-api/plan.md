# Implementation Plan: List Renter Contacts API

**Branch**: `sprint/003` | **Date**: 2026-06-05 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/041-list-contacts-api/spec.md`

## Summary

Add a `GET /api/v1/contacts` endpoint to the existing `contacts` module that returns a paginated, tenant-scoped list of active renter contacts ordered by creation date descending. No new Prisma model or migration is required — only an additional repository method, use case, query DTO, response DTO, and controller route added to the existing `ContactsModule`.

## Technical Context

**Language/Version**: TypeScript 5.x / Node.js 20.x
**Primary Dependencies**: NestJS 10, Prisma 5, class-validator, class-transformer (`@Type`), @nestjs/swagger
**Storage**: PostgreSQL (via existing `PrismaService`)
**Testing**: Jest (unit, integration, E2E)
**Target Platform**: Linux server (Docker / Railway)
**Project Type**: Web service API (NestJS monolith — additive change only)
**Performance Goals**: < 2 seconds end-to-end per SC-001
**Constraints**: Results must exclude soft-deleted contacts (`deletedAt IS NULL`); offset-based pagination (page + limit); `tenantId` always from JWT context; no search/filter in scope
**Scale/Scope**: One new `GET` route, one new use case, one repository method extension — no schema changes
