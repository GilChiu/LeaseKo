# Implementation Plan: Tenant Isolation Request Lifecycle Enforcement

**Branch**: `010-tenant-isolation-lifecycle` | **Date**: 2026-05-03 | **Spec**: [spec.md](spec.md)

## Summary

Formalize and complete the tenant isolation enforcement layer for the NestJS backend. Features 008 and 009 implemented JWT verification, `tenantId` extraction from `payload.o?.id`, and the `@RequiresTenant()` decorator. This feature adds the missing `@UserOnly()` decorator, the verification endpoint `GET /tenant-context`, and corrects stale documentation. No database work is required.

**Tenant ID Strategy (Normative)**:
- Source: Clerk JWT compact v2 claim `o.id` — verified server-side via `@clerk/backend` `verifyToken()`
- Trust boundary: JWT only — NEVER from request body, query parameters, or arbitrary headers
- Absent `tenantId` on a `@RequiresTenant()` route → `403 Forbidden` (no detail exposed)
- Default (no decorator): JWT required, `tenantId` may be null

### Step 1 — Create `@UserOnly()` Decorator

**File**: `apps/api/src/common/decorators/user-only.decorator.ts` (NEW)

```typescript
import { SetMetadata } from '@nestjs/common';

export const IS_USER_ONLY_KEY = 'isUserOnly';
export const UserOnly = (): MethodDecorator & ClassDecorator =>
  SetMetadata(IS_USER_ONLY_KEY, true);
```

**Why**: Provides explicit opt-in for routes that require authentication but not tenant context. Makes developer intent legible in code.

---

### Step 2 — Update `ClerkJwtGuard` to Respect `@UserOnly()`

**File**: `apps/api/src/common/guards/clerk-jwt.guard.ts` (MODIFY)

Add import of `IS_USER_ONLY_KEY`. After setting `request.user`, check `IS_USER_ONLY_KEY` before checking `IS_TENANT_REQUIRED_KEY`:

```
if @UserOnly() → skip tenant check, return true
if @RequiresTenant() AND tenantId === null → throw ForbiddenException()
else → return true
```

Full updated `canActivate` logic:

```typescript
async canActivate(context: ExecutionContext): Promise<boolean> {
  const isPublic = this.reflector.getAllAndOverride<boolean>(IS_PUBLIC_KEY, [
    context.getHandler(), context.getClass(),
  ]);
  if (isPublic) return true;

  const request = context.switchToHttp().getRequest<Request>();
  const token = this.extractBearerToken(request);
  if (!token) throw new UnauthorizedException();

  const { userId, tenantId } = await this.verifyClerkToken.execute(token);
  (request as Request & { user: IRequestContext }).user = { userId, tenantId, role: null };

  const isUserOnly = this.reflector.getAllAndOverride<boolean>(IS_USER_ONLY_KEY, [
    context.getHandler(), context.getClass(),
  ]);
  if (isUserOnly) return true;  // ← skip tenant check

  const isTenantRequired = this.reflector.getAllAndOverride<boolean>(IS_TENANT_REQUIRED_KEY, [
    context.getHandler(), context.getClass(),
  ]);
  if (isTenantRequired && !tenantId) throw new ForbiddenException();

  return true;
}
```

**Why**: `@UserOnly()` must explicitly skip the tenant check even if `@RequiresTenant()` is also present (defensive; prevents accidental double-decoration bugs).

**File**: `apps/api/src/modules/tenant-context/presentation/tenant-context.controller.ts` (NEW)

```typescript
import { Controller, Get } from '@nestjs/common';
import {
  ApiBearerAuth, ApiForbiddenResponse, ApiOkResponse,
  ApiOperation, ApiTags, ApiUnauthorizedResponse,
} from '@nestjs/swagger';
import { CurrentTenant } from '../../../common/decorators/current-tenant.decorator';
import { RequiresTenant } from '../../../common/decorators/requires-tenant.decorator';

@ApiTags('tenant-context')
@ApiBearerAuth()
@Controller('tenant-context')
export class TenantContextController {
  @Get()
  @RequiresTenant()
  @ApiOperation({ summary: 'Get current tenant context' })
  @ApiOkResponse({
    description: 'Active tenant context.',
    schema: { example: { tenantId: 'org_2abc123xyz' } },
  })
  @ApiUnauthorizedResponse({ description: 'Missing or invalid Bearer token.' })
  @ApiForbiddenResponse({ description: 'Authenticated but no active organization context.' })
  getTenantContext(@CurrentTenant() tenantId: string): { tenantId: string } {
    return { tenantId };
  }
}
```

## Error Behavior

| Scenario | Response | Detail Exposed |
|----------|----------|----------------|
| No `Authorization` header | `401 Unauthorized` | None |
| Malformed / expired JWT | `401 Unauthorized` | None |
| JWT valid, `sub` absent | `401 Unauthorized` | None |
| JWT valid, `tenantId` null on `@RequiresTenant()` route | `403 Forbidden` | None |
| All checks pass | `200` | Route-specific payload |

All errors pass through `GlobalExceptionFilter` → `{ statusCode, message, path, timestamp }`.

---

## Security Rules

1. `tenantId` is ONLY derived from `payload.o?.id` in the **server-verified** Clerk JWT.
2. `tenantId` from request body, query parameters, or headers is IGNORED entirely — no code path reads it from those sources.
3. `ForbiddenException()` is thrown with **no arguments** — no message leakage about why tenant context is absent.
4. `UnauthorizedException()` is thrown with **no arguments** — no message leakage about JWT structure.
5. `GlobalExceptionFilter` sanitizes all error responses — raw Clerk claims never reach the HTTP response body.
6. `StubBearerGuard` is deprecated and never registered — it must not be used.

## Notes for Next Features

### Feature 011: Prisma Integration + Base Schema

- Every new Prisma model MUST include `tenantId String` with `@@index([tenantId])`
- Repository interfaces must accept `tenantId: string` as a required parameter
- Pattern: `findAll(tenantId: string)` not `findAll()` — enforced by interface contract

### Feature 012: Tenant-Safe Query Helpers

- Consider a `TenantScopedRepository<T>` base class that enforces `tenantId` on all methods
- `IRequestContext` can be passed whole to use cases; use cases pass `tenantId` to repositories

### Feature 013+: RBAC / Permissions

- `role` field in `IRequestContext` is reserved — currently always `null`
- Role resolution will require a DB lookup (User → TenantUser → role)
- A new `RoleGuard` should be layered on top of the existing `ClerkJwtGuard` flow
- `@Roles('owner', 'manager')` decorator pattern recommended

### Feature 014+: BullMQ Job Propagation

- Every job payload MUST include `{ tenantId: string, userId: string }`
- Extract from `IRequestContext` in the service/use-case that enqueues the job
- Never enqueue a job without tenant context from an authenticated request
