# Implementation Plan: Get Renter Contact by ID

**Branch**: `sprint/003` | **Date**: 2026-06-05 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/042-get-contact-by-id/spec.md`

## Summary

Add a `GET /api/v1/contacts/:id` endpoint to the existing `contacts` module that retrieves a single active renter contact scoped to the authenticated session's workspace. Non-existent, cross-tenant, and archived contacts all return an identical 404. No schema changes, no new DTOs — only a new repository method, use case, and controller route.

## Technical Context

**Language/Version**: TypeScript 5.x / Node.js 20.x
**Primary Dependencies**: NestJS 10, Prisma 5, @nestjs/swagger
**Storage**: PostgreSQL (via existing `PrismaService`)
**Testing**: Jest (unit, integration, E2E)
**Target Platform**: Linux server (Docker / Railway)
**Project Type**: Web service API (NestJS monolith — additive change only)
**Performance Goals**: < 2 seconds end-to-end per SC-001
**Constraints**: Cross-tenant/archived/missing IDs must return identical 404 (information leakage prevention); no path parameter format validation; `deletedAt` never in response
**Scale/Scope**: One new `GET /:id` route, one new use case, one repository method — no schema changes

## Constitution Check

_GATE: Must pass before Phase 0 research. Re-check after Phase 1 design._

**Architecture**

- [x] Additive to existing four-layer `contacts` module — no structural changes
- [x] `GetTenantContactByIdUseCase` delegates to repository interface — no Prisma in use case
- [x] Controller remains thin — throws `NotFoundException` when use case returns null

**Multi-Tenancy (CRITICAL)**

- [x] `findById(id, tenantId)` filters by both `id` AND `tenantId` — cross-tenant IDs never resolve
- [x] `tenantId` sourced from `@CurrentTenant()` — never from path, query, or body

**Authentication & Authorization**

- [x] `@RequiresTenant()` on `GET /:id` — returns 403 if no active workspace
- [x] Existing `ClerkJwtGuard` unchanged

**Data Layer**

- [x] `findById` implemented only in `PrismaTenantContactRepository`
- [x] No schema changes — `TenantContact` model already has `deletedAt`

**API & Async**

- [x] Endpoint documented with full Swagger decorators
- [x] No request body or query DTO needed — only `@Param('id')`
- [x] No BullMQ — point lookup is synchronous and fast

**Testing**

- [x] Unit test: `GetTenantContactByIdUseCase` — found, not found (null from repo → NotFoundException)
- [x] Integration test: `findById` in `PrismaTenantContactRepository`
- [x] E2E test: `GET /contacts/:id` — 200, 404 (missing), 404 (cross-tenant), 404 (archived)

**Security**

- [x] No secrets in source code
- [x] Rate limiting: existing `ThrottlerGuard` covers the route automatically
- [x] All three not-found cases return identical 404 — no information leakage
